# Архитектура и контракты

- gateway :8080 маршрутизирует REST к devices и telemetry; /healthz проверяет сам процесс.
- devices хранит реестр в PostgreSQL и публикует команды MQTT QoS1, без retain.
- telemetry подписывается на ventilation/+/state, сохраняет историю в PostgreSQL и последнее состояние в Redis (TTL 120 секунд). REST возвращает последнее состояние, при отсутствии кеша — из БД.
- Общая PostgreSQL в MVP; devices владеет таблицей devices, telemetry — таблицей telemetry. При масштабировании разделить роли и базы.

REST: GET/POST /api/devices, POST /api/devices/{id}/position, GET /api/telemetry/{id}.
ID: 1–64 символа ASCII, буквы, цифры, дефис или подчёркивание.
Команда и состояние MQTT: {"position":50}, целое 0–100. Телеметрия публикуется каждые 10 секунд и после команды.
202 означает принятие брокером, а не подтверждение физического перемещения. Команды офлайн-устройствам не ставятся в очередь.
API состояния добавляет received_at в UTC. Старое состояние из БД не означает, что устройство онлайн.
QoS1 может создавать повторные записи; перед production добавить event_id и дедупликацию.
Прошивка при старте устанавливает 0%; при потере связи сохраняет последнюю позицию. Настроить безопасную позицию и watchdog под оборудование.

Это локальный development стенд: нет API авторизации, MQTT TLS/ACL и автоматического управления по CO₂/температуре.
Не открывать его в интернет. Перед production добавить идентификацию устройств, секреты, TLS, ACL, аудит команд, подтверждения с command_id, outbox, ограничения хранения истории и наблюдаемость.

Caddy — внешняя REST-точка на http://localhost:8080. Gateway не публикует порт на хост. Expo использует LAN IP с тем же портом. Настройки: infra/caddy/Caddyfile. Для production указать домен, открыть 80/443 и настроить HTTPS.
